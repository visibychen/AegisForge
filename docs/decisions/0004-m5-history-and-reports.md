# ADR 0004：工作台历史、归档候选和报告凭证

日期：2026-11-10，关联 M5 / Issue #6，继承 ADR0003 的执行隔离。

历史使用逻辑移出：0006 增加 deleted_at，禁止移出活动检测/修复/动态验证；所有任务、发现和修复入口在父任务移出后返回404，worker/runner也检查。账务、共享输入保留，输入仍可按 artifact ID 预览；这不是物理擦除。界面明确“移出历史”及保留内容。物理清除和引用回收延后单独设计，不能声称已交付隐私擦除。存在移出记录时拒绝降级0006，避免删除标记丢失而恢复历史。

父检测重试后，旧候选允许查看、下载及按原 attempt 对比，但标记 archived。baseline_for 可显式取原 attempt。旧候选不得新申请动态验证，409 REPAIR_ARCHIVED；runner对已排队请求也终结为同名错误，不执行容器。取消路径保留，已完成的旧动态记录不改写；已在运行的旧验证仍可能完成，其结果只能展示在归档候选上。当前与归档计数分开，父重试使前端候选重新加载。

发现筛选与统计使用 SQLite JSON 表达式，payload 仍为唯一事实来源，不新增重复的漏洞元数据列。历史修复总量由SQL精确分组，不让300条截断冒充总量；总览的当前候选裁决重算有300条上限，明确样本数、上限与总数。对比按位置归并并保留 rule/llm 各自分类，显示最严重分类的同时展示来源差异。复检未完成时不能从零位置推断无风险。

长源码采用每窗口500行的有界DOM，完整内容只分行一次，行号为绝对行号。选定证据、键盘End/N/P以及改动导航可切换窗口；去掉末尾分隔符产生的幽灵行，窗口由光标派生。纯文本渲染，不注入HTML。

report-2.1 默认排除源码、文件名、HTTP参数名、证据及模型自由文本，输出结构化发现、覆盖、旧尝试与修复说明卡。报告在显式SQLite读事务内组装，BEGIN位于首次读取之前，避免跨查询混合快照；报告大小上限4MiB，发现1000条、修复200张卡的上限均显式标注截断。

JSON content_digest 对排除 generated_at/content_digest 的规范内容加域分隔后做SHA256。Markdown展示同一个JSON摘要，**不覆盖Markdown自身文字**；不是签名，不证明模型正确，不防御可重算摘要的写入者。离线校验器只读有界常规文件，拒绝重复键、非有限数、版本不符、缺字段、超限与摘要不匹配，不执行内容、不回显输入。

沿用既有Compose架构：API/worker无Docker CLI/socket，受信控制器独占socket且不加载候选；候选只在隔离子容器执行。新增GitHub干净Ubuntu Compose浏览器验收，不传模型key，只用fake，随机API token在日志中掩码，等待服务就绪，实际检查隔离并运行默认浏览器场景。CI失败不会被continue-on-error掩盖；是否设为仓库必需检查由GitHub规则决定，本轮不擅改保护规则。一次性CI data设0777只为兼容runner UID和容器UID1000，不作为正式部署建议。
