说明：
1. 行号为该请求在 bundle 文件中的行号（请求行/头/体所在行），不是样例内行号。
2. "解码"只做离线还原：URL 一次/二次解码、JSON 解析、base64 解码；未访问任何地址、
   未发送请求、未对真实站点做任何测试。
3. 判断只针对"请求是否携带该类攻击特征"，不据此断言服务端存在漏洞。
4. 结论均为 agree（A=attack、N=normal），逐条理由见《样例复核记录.txt》第七、八节；
   本表提供可复核的原文与解码值。

三、附注
--------------------------------------------------------------------
1. 上表 60 条与 manifest 的 cwe/anchor 一一对应；N 样本的 cwe 为 null，表示正常对照无类别，
   不是漏标。
2. 二次编码（HTTP-XSS-03-A）与 base64（HTTP-XSS-10-A）都给出了中间解码值，避免把"编码后的
   文本"误当普通文本，也避免只看编码形式就判攻击。
3. 正常样本中的 <3、union、sleep、双连字符、$ 金额、Markdown 反引号、||、& 连词、管道版本号、
   Windows 路径都是刻意设计的"相似字符/关键词但非攻击"对照；本表说明它们为什么仍属正常。
4. 副本中未出现真实域名/IP；Host 使用 .test 保留域，SQLI-09-N 使用 203.0.113.0/24 与
   198.51.100.0/24 文档段。本次未发出任何请求。
